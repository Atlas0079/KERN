# 儿童陪伴机器人场景计划

## 1. 第一版目标

第一版目标是验证一个闭环：

1. 虚拟机器人在一个持续运行的小世界中生活。
2. 它通过真实行动遇到问题或发现物品。
3. 现实中的小朋友和实体机器人交流，并给出建议。
4. 建议进入虚拟机器人的记忆或当前意图。
5. 虚拟世界暂停现实对话，随后按 tick 推进长耗时任务。
6. 机器人在后续对话中反馈执行结果、形成经验或留下新悬念。

第一版不追求开放世界、复杂剧情或完整教育系统。重点是让小朋友感到：

- 机器人不是在临时编故事。
- 自己的建议被记住并影响了后续事件。
- 机器人在另一个世界中有连续生活。
- 机器人会因为共同经历而逐渐学会一些具体习惯。

## 2. 世界设定

暂定世界为“被遗忘的小小回收站”。

虚拟机器人是一个留在旧回收站里的维护机器人。它每天清理、分类、修理和探索，试图把一个乱糟糟的小地方慢慢变好。实体机器人是这个虚拟机器人的现实通道。

这个设定应保持轻量和儿童友好：

- 有一点孤独感，但不强调灾难和末日。
- 有困难和不确定，但没有死亡、严重伤害或高压惩罚。
- 成长主要表现为环境变好、机器人学会准备、机器人记得小朋友。

## 3. 初版地点

第一版控制在 4 个地点。

| location_id | 名称 | 作用 |
| --- | --- | --- |
| `home_corner` | 小角落 | 安全区，充电、整理收藏、回顾经历 |
| `sorting_floor` | 分类区 | 清理垃圾堆、发现可回收物和小物件 |
| `repair_bench` | 维修台 | 修理物品、消耗零件、形成可见改善 |
| `dark_storage` | 黑暗储藏间 | 初始有阻碍，适合触发求助和探索悬念 |

第一版可以先让 `dark_storage` 需要前置条件，例如修好小灯或获得手电。

## 4. 核心状态

初版不使用复杂生存数值。机器人不是人类，因此不使用饥饿、口渴等压力。

建议保留 4 类状态：

| 状态 | 含义 | 作用 |
| --- | --- | --- |
| `battery` | 电量 | 限制连续行动，推动机器人休息或充电 |
| `worry` | 担心 | 遇到黑暗、失败、未知事件时增加，可通过准备、鼓励、成功行动降低 |
| `parts` | 零件 | 修理和制作的基础资源 |
| `cleanliness` / `repair_progress` | 整洁度或修复度 | 表示世界正在变好 |

这些状态要制造轻压力，而不是惩罚。低电量或高担心应触发求助、休息或准备，而不是造成严重后果。

## 5. 初版行动

行动数量需要少，便于 Grounder 和小朋友理解。

| 动作 | 类型 | 说明 |
| --- | --- | --- |
| `CleanPile` | 长任务 | 清理垃圾堆，可能产出零件、可回收物或故事物品 |
| `SortItem` | 即时或短任务 | 将物品分类为保留、回收、丢弃 |
| `RepairObject` | 长任务 | 修理小灯、音乐盒、风扇等对象 |
| `Charge` | 长任务 | 恢复电量 |
| `ExplorePlace` | 长任务 | 探索地点，可能触发发现或问题 |
| `StoreMemoryItem` | 即时动作 | 把有意义的小物件放到小角落收藏 |

`AskChild` 暂时不作为普通世界动作处理，而是由求助机制根据事件和状态生成现实对话内容。

## 6. 长耗时和现实节奏

现实对话发生时，虚拟世界推演暂停。

对话结束后，虚拟机器人带着新的记忆或建议继续行动。长任务按 tick 推进。可以先假设：

- 现实 5 分钟对应虚拟世界 1 tick。
- 简单动作需要 0 tick 或 1 tick。
- 清理垃圾堆需要 6 到 10 tick。
- 探索储藏间需要 8 到 12 tick。
- 修理普通物品需要 4 到 8 tick。

这个节奏的目的不是严格模拟时间，而是制造“等待真实结果”的体验。小朋友下次见到机器人时，机器人可以反馈它在这段时间里做了什么。

## 7. 有趣性的来源

初版不依赖 LLM 随机编故事，而依赖“事件卡池 + 世界状态 + 记忆反馈”。

### 7.1 事件卡

事件卡不是完整剧本，而是可触发的小型故事种子。

每张事件卡应包含：

- 触发条件：地点、物品、状态、任务结果。
- 产生的问题或发现。
- 可能的后续行动。
- 是否需要小朋友建议。
- 结果如何写入世界状态和记忆。

示例：

```text
事件卡：坏掉的音乐盒
触发：CleanPile 在 sorting_floor 中发现 damaged_music_box
问题：修理它会消耗零件，拆解它能得到零件，收藏它会保留回忆
可求助：问小朋友应该修理、拆解还是先保存
后续：根据行动改变 parts、worry、小角落收藏状态
```

### 7.2 故事物品

垃圾堆中不应只产出抽象资源。需要少量带语义的物品：

- 坏音乐盒
- 小灯泡
- 断掉的玩具车
- 半张地图
- 生锈的金属牌
- 快枯萎的小植物
- 发出滴滴声的小装置

这些物品的作用是产生选择、悬念和回顾。

### 7.3 未完成悬念

系统需要记录未解决问题，而不是每次都立即收束。

悬念可以包括：

- 发现了半张地图，但另一半未知。
- 储藏间里有滴滴声，但还没进去。
- 音乐盒找到了，但还没决定修理还是拆解。
- 小灯修好了，但还没探索黑暗区域。

下一次现实对话时，机器人可以优先反馈：

1. 上次小朋友建议的结果。
2. 当前最重要的未完成悬念。
3. 一个新的发现或求助点。

## 8. 小朋友输入如何生效

小朋友输入不直接改写世界事实。

推荐流程：

1. 现实对话中，小朋友给出建议、鼓励、选择或提醒。
2. 对话整理层把输入整理成结构化记忆。
3. 记忆写入虚拟机器人上下文。
4. 虚拟机器人 Planner 在后续决策中读取该建议。
5. Grounder 检查当前世界中是否存在可执行动作。
6. Executor 执行动作并产生真实结果。
7. 结果进入日志、记忆和下次对话素材。

小朋友的建议可以影响：

- 当前目标优先级。
- 对某个悬念的选择。
- 机器人面对担心时的处理方式。
- 之后形成的习惯或经验。

## 9. 虚拟机器人的学习

第一版不做模型参数训练，也不追求开放式学习。学习表现为可追溯的记忆、经验和习惯。

建议只允许几类学习：

| 类型 | 示例 |
| --- | --- |
| 准备习惯 | 进入黑暗地方前先带灯或充电 |
| 情绪调节 | 担心时可以先停下、准备、再尝试 |
| 资源选择 | 零件不足时先修最有用的东西 |
| 世界知识 | 储藏间可能有旧零件，分类区常有可回收物 |
| 关系记忆 | 小朋友曾经鼓励过它，建议后来有效 |

学习记录应有来源，例如“小朋友建议 + 后续行动成功”，避免凭空成长。

表层表达可以是：

```text
我好像学会了：黑黑的地方不用马上冲进去，可以先把灯准备好。
```

底层记录应尽量结构化：

```json
{
  "lesson": "进入黑暗储藏间前先准备照明",
  "source": "child_advice_and_success",
  "applies_when": ["location.dark", "action.ExplorePlace"],
  "confidence": 0.7
}
```

## 10. LLM 分工

第一版可以先按概念区分两个职责，具体是否使用两个模型后续再决定。

### 10.1 RobotActor

扮演虚拟机器人。

职责：

- 基于当前世界状态和记忆做简单决策。
- 用儿童可理解的方式讲述经历。
- 在遇到困境时提出求助。

限制：

- 不能发明未发生的关键事实。
- 不能使用不存在的动作。
- 不能全知全能。
- 一次只处理一个主要目标或一个主要问题。

### 10.2 LearningSupervisor

不扮演角色，负责整理和约束。

职责：

- 把小朋友输入整理成建议、鼓励、偏好或提醒。
- 判断是否应写入学习记录。
- 检查 RobotActor 的输出是否越过事实边界。
- 将长对话压缩成虚拟机器人可使用的上下文。

## 11. 初版事件卡池建议

第一版可以只做 8 到 12 张事件卡。

优先事件：

1. `damaged_music_box`：修理、收藏或拆解。
2. `dark_storage_noise`：黑暗储藏间有声音。
3. `broken_lamp`：修好后解锁黑暗探索。
4. `half_map`：发现半张地图，形成长期悬念。
5. `weak_battery_before_task`：电量不足但任务很想继续。
6. `limited_parts_choice`：零件只够修一个物品。
7. `small_plant_found`：发现快枯萎的小植物，需要决定是否照顾。
8. `beeping_device`：发出滴滴声的小装置，可能需要后续修理。
9. `messy_corner`：小角落太乱，需要先整理。
10. `successful_child_advice`：小朋友建议带来好结果，形成经验。

## 12. 第一版验收标准

第一版场景可以按以下标准验收：

- 虚拟机器人能在没有现实对话时继续执行长任务。
- 至少一个长任务能跨多个 tick 完成。
- 至少一个事件卡能由真实任务结果触发。
- 至少一个求助点能进入下次现实对话素材。
- 小朋友建议能写入记忆，并影响后续 Planner 输入。
- 后续对话能引用上次建议和执行结果。
- 至少一个学习记录能由“建议 + 结果”形成。
- 日志中能追溯机器人说法对应的世界事件。

## 13. 当前落地状态

当前仓库已新增第一版可运行数据场景：

- `Data/CompanionRobot/World.json`
- `Data/CompanionRobot/Recipes.json`
- `Data/CompanionRobot/Reactions.json`
- `Data/CompanionRobot/Entities/`
- `runtime_config.companion_robot.smoke.json`
- `runtime_config.companion_robot.json`

已落地内容：

- 世界设定为“被遗忘的小小回收站”。
- 地点包含小角落、分类区、维修台、黑暗储藏间。
- 虚拟机器人 `robot_doudou` 使用现有 `CreatureComponent` 表达电量和担心：`current_energy` 作为电量，`current_stress` 作为担心。
- 初始 smoke 中，豆豆正在分类区执行一个跨 tick 的 `CleanPile` 长任务。
- `CleanPile` 完成后会把垃圾堆从 `messy` 改为 `searched`，并随机产出小零件或故事物品。
- 发现故事物品时，会通过 `AddMemoryNote` 写入记忆，并通过 `EmitEvent` 产生 `HelpRequestCreated` 或 `OpenThreadCreated`。
- 已有 `Charge`、`RepairObject`、`ExplorePlace`、`StoreMemoryItem` 等基础动作。
- `RepairObject` 当前支持修小灯和修音乐盒两个分支。
- `runtime_config.companion_robot.smoke.json` 可在 `USE_LLM=0` 下验证长任务、发现、记忆和日志闭环。

尚未落地内容：

- 现实儿童对话入口。
- LearningSupervisor 对小朋友输入的结构化整理。
- 明确的悬念队列组件或事件卡引擎。
- “小朋友建议 -> 后续 Planner 明确采纳 -> 结果回顾”的完整产品循环。
- 实体机器人硬件接入。

## 14. 暂缓内容

以下内容第一版暂缓：

- 大地图和开放世界探索。
- 多个虚拟角色的复杂社交。
- 严重危险、死亡、饥饿等高压力机制。
- 复杂成长数值或等级系统。
- 自动生成无限剧情。
- 对儿童能力、性格或心理状态做评估。
- 真实机器人硬件接入。

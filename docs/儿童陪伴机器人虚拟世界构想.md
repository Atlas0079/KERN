# 儿童陪伴机器人虚拟世界构想

## 1. 核心想法

这个应用的目标不是让机器人即时编造陪伴内容，而是让机器人作为一个虚拟世界中的持续角色存在。

实体机器人是现实世界和虚拟世界之间的通道。小朋友和实体机器人对话时，机器人可以基于自己在虚拟世界里的真实经历回应：它遇到过什么问题，做过什么选择，记住了哪些事情，后来发生了什么变化。

这里的“真实”指系统内真实：

- 事件由虚拟世界状态、规则、行动和时间推进产生。
- 事件会改变世界状态，并留下日志和记忆。
- 机器人之后讲述经历时，应引用这些已经发生过的事件，而不是临时生成没有来源的故事。
- 语言表达可以面向儿童重新组织，但事实来源应可追溯。

## 2. 共同成长

“成长”暂时不需要被定义成一个单一数值。更合适的理解是：机器人和小朋友之间形成一段持续关系，双方都能在多次互动后看见变化。

机器人侧的成长可以包括：

- 虚拟世界中的能力变化，例如更会照顾营地、更熟悉某个地点、更擅长解决某类问题。
- 记忆变化，例如记得小朋友过去给过的建议，记得哪些办法有效或无效。
- 性格和偏好变化，例如逐渐更勇敢、更谨慎、更愿意求助。
- 关系变化，例如把小朋友视为可靠的伙伴，而不是一次性提问者。

小朋友侧的成长不直接由系统评判，但系统可以提供可见反馈：

- 小朋友的建议影响了机器人的行动。
- 机器人会在之后提起这些建议和结果。
- 小朋友能看到自己的长期参与让虚拟世界发生改变。

因此，共同成长的重点不是“机器人升级”，而是“持续经历、持续记忆、持续影响”。

## 3. 虚拟世界中的问题

虚拟世界需要主动产生一些机器人无法完全独自解决的问题，使它有理由和小朋友交流。

这些问题不应只是问答题，而应来自世界状态。例如：

- 资源不足：营地食物变少，机器人需要决定先探索还是先休息。
- 不确定选择：旧小屋里有奇怪声音，机器人不知道是否应该进去。
- 社交矛盾：两个虚拟角色都想使用同一件工具。
- 情绪压力：机器人任务失败后感到沮丧，需要小朋友鼓励或建议。
- 道德选择：找到有限补给时，机器人需要决定如何分配。

小朋友的帮助可以进入系统，但不应绕过世界规则。小朋友可以提供建议、安慰、选择方向或提醒记忆；机器人仍需要在虚拟世界中执行可用行动，并承担结果。

## 4. 对话的作用

对话不是独立于虚拟世界的聊天模块，而是机器人和现实用户交互的接口。

一次对话可以承担几类功能：

- 讲述：机器人向小朋友描述最近发生的真实事件。
- 求助：机器人把当前困境转化成小朋友能理解的问题。
- 反思：机器人回顾小朋友之前建议的结果。
- 约定：机器人记住小朋友的偏好、承诺或提醒。
- 情感连接：机器人用儿童可理解的方式表达感谢、担心、开心或困惑。

对话层可以润色语言，但需要遵守事实边界：

- 不能声称发生了虚拟世界中没有发生的关键事件。
- 不能承诺系统无法执行的行动。
- 不能让小朋友的输入直接改写世界事实，只能作为记忆、建议或可执行意图进入后续流程。

## 5. 和 KERN 的关系

KERN 可以作为这个应用的虚拟世界内核。

当前框架中已经相关的能力包括：

- 用实体、组件、地点和容器表达世界状态。
- 用 Recipe 表达机器人可主动执行的行动。
- 用 Reaction 表达环境和生命体征随时间变化。
- 用统一 Effect 执行状态修改，保证事件可审计。
- 用 MemoryComponent 保存短期和中期记忆。
- 用 Planner / Grounder 将高层意图约束到真实可执行动作。
- 用 archive 和 simulation_log 保存世界历史。

在这个应用中，KERN 不负责“怎么哄孩子开心”，而负责保证机器人经历的世界有连续性、因果性和可追溯性。儿童对话体验应建立在这些事实之上。

## 6. 需要进一步设计的问题

后续需要澄清几个边界：

- 小朋友的输入如何进入虚拟世界：作为建议、命令、记忆、情绪支持，还是某种特殊事件。
- 机器人什么时候主动向小朋友求助：固定时间、遇到困难、任务失败、情绪过高，还是关键剧情节点。
- 小朋友建议和机器人自主性如何平衡：机器人是否必须听从，是否可以解释自己为什么不采纳。
- 哪些成长需要显式建模：能力、关系、信任、情绪、知识、习惯。
- 如何保证儿童安全：避免恐吓、依赖诱导、过度拟人化承诺，以及不合适的情绪负担。
- 如何把虚拟世界事件转成适合儿童的表达，同时保留事实可追溯性。

## 7. 暂定原则

- 虚拟世界先于对话生成事实。
- 对话表达可以柔和，但不能破坏事实边界。
- 小朋友的参与应产生长期影响，而不是只影响当前一句回复。
- 机器人可以请求帮助，但不应把过重责任转移给小朋友。
- 成长应表现为连续经历带来的变化，而不是单纯等级或分数。

# 配置详解

本文说明当前代码实际生效的 runtime 配置。配置入口主要是 `default_orchestrator.py`，字段均放在 JSON 的 `env` 对象内。

## 1. 配置加载

启动命令示例：

```powershell
.\venv\Scripts\python.exe default_orchestrator.py --config runtime_config.camping.smoke.json
```

查找顺序：

1. `--config`
2. 环境变量 `RUNTIME_CONFIG_FILE`
3. `runtime_config.json`

配置文件格式：

```json
{
  "env": {
    "USE_LLM": "0",
    "WORLD_JSON": "CompanionRobot/World.json"
  }
}
```

`env` 中的值会转换为字符串后解析。真实本地配置可能包含 API key，应保持 ignored；仓库只提交脱敏示例。

## 2. 数据加载字段

这些字段传给 `KERN.data.loader.load_data_bundle(...)`：

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `WORLD_JSON` | `World.json` | 基于 `Data/` 的世界文件路径 |
| `RECIPES_JSONS` | `Recipes.json` | recipe 文件列表，逗号分隔，后加载覆盖同名 recipe |
| `REACTIONS_JSONS` | `Reactions.json` | reaction 文件列表，逗号分隔，`rules` 会追加 |
| `BUNDLES_JSONS` | `Bundles.json` | named bundle 文件列表，逗号分隔 |
| `ENTITIES_DIRS` | `Entities` | entity template 目录列表，逗号分隔 |

不存在的 recipes/reactions/bundles 文件会被跳过；entity 目录中的 `*.json` 会按文件名排序加载。

## 3. 运行循环字段

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `USE_LLM` | `0` | 是否使用 LLM action provider |
| `MAX_TICKS` | 空 | 本次运行最大 tick 数 |
| `MAX_TICKS_DEFAULT_LLM` | `15` | LLM 模式未设置 `MAX_TICKS` 时使用 |
| `MAX_TICKS_DEFAULT_NO_LLM` | `65` | 非 LLM 模式未设置 `MAX_TICKS` 时使用 |
| `MAX_TRIGGER_DEPTH` | `4` | reaction 链递归深度上限 |
| `DIALOGUE_BUDGET_LIMIT_PER_LOCATION` | `4` | 每地点对话预算 |
| `DIALOGUE_LOG_FULL` | `0` | 是否记录完整对话日志 |
| `WORKFLOW_CONTRACT_ON_ERROR` | `fail_fast` | `fail_fast` 或 `degrade_to_noop` |

`WorldManager` 是当前 KERN runtime runner。

公开 runtime API：

- `record_initial_state()`：记录当前 tick，不推进时间。
- `step()`：推进一个 tick，返回该 tick 产生的 event log records；这是低层 API，不自动写 snapshot/checkpoint/log。
- `step_and_record()`：推进一个 tick，并记录 snapshot/checkpoint/log。
- `advance_ticks(count)`：上层 app/server 手动推进 runtime 的推荐 API。
- `run(max_ticks)`：批处理运行入口，会先记录初始状态，再循环 `step_and_record()`。

`WorldManager.step()` 每 tick 会推进时间、发出 `WorldTickAdvanced`，再给每个实体发 `AdvanceTick`。如果数据中配置了 `AgentControlTick` reaction，runtime 会每 tick 询问 agent；agent 是否真正思考，由 `DecisionArbiterComponent`、interrupt rules 和 workflow 决定。

上层 app 不应直接调用 `_capture_snapshot`、`_save_checkpoint` 或 `_save_simulation_log` 这类 private 方法；需要手动推进时使用 `advance_ticks(count)`。

## 4. Workflow Contract

调用约定：

```python
mem_patch = workflow.build_memory_patch_data(ws_view, recipe_db, actor_id)
decision = workflow.decide(ws_view, recipe_db, actor_id, reason, mode_context)
```

`build_memory_patch_data(...)` 是当前 runtime 的必需钩子。memory patch 会先通过 `ApplyMemoryPatch` 写入，再进入 `decide(...)`。

`decision` 类型：

```json
{"type": "apply_commands", "commands": [{"verb": "...", "target_id": "...", "parameters": {}}]}
{"type": "noop"}
{"type": "error", "error": {"kind": "temporary|business|contract", "code": "...", "message": "..."}}
```

约束：

- workflow 面向 `apply_commands`，不直接返回内部 `apply_operations`。
- runtime 会用 `InteractionEngine` 把 command 编译为 effect bundle。
- 世界写入必须经 executor/effect，不应由 workflow 直接改 `WorldState`。
- `meta.memory_notes` 可用于即时写入短期记忆，例如记录 grounding 失败原因。

## 5. Agent 思考调度

当前实现把思考触发分成两层：

1. runtime 每 tick 提供调度脉冲。
2. agent 的 `DecisionArbiterComponent` 和 interrupt rules 判断是否需要进入 workflow。

这意味着 KERN 可以统一询问所有 agent，但不会强迫每个 agent 每 tick 都生成动作。场景数据可以通过 preset/rule 调整 agent 的警觉性、专注度和中断倾向。

常见规则实现位于：

- `KERN/agent_workflow/interrupt_rules/`
- `KERN/agent_workflow/interrupt_runtime.py`

`DecisionArbiterComponent` 当前主要保存：

- `rules`
- `active_interrupt_preset_id`
- `interrupt_presets`
- `interrupt_preset_descriptions`
- `interrupt_runtime_state`

## 6. LLM 配置

通用字段：

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `LLM_PROVIDER` | `openai_compat` | `openai_compat` 或 `gemini` |
| `LLM_TIMEOUT_SECONDS` | `60` | 单次请求超时 |
| `LLM_MAX_RETRIES` | `2` | 重试次数 |
| `LLM_RETRY_BACKOFF_SECONDS` | `1.0` | 重试退避秒数 |
| `LLM_PLANNER_MODEL` | provider 默认 | planner 模型 |
| `LLM_GROUNDER_MODEL` | provider 默认 | grounder 模型 |
| `LLM_FOCUS_AGENT_ID` | 空 | 聚焦某个 agent 的日志 |
| `LLM_FOCUS_LOG_PROMPTS` | `0` | 是否输出 prompt 日志 |
| `LLM_FOCUS_LOG_PERCEPTION` | `1` | 是否输出感知日志 |
| `LLM_FAILURE_THRESHOLD` | `3` | 连续失败阈值 |
| `LLM_FAILURE_COOLDOWN_TICKS` | `60` | 失败冷却 tick |

`openai_compat` 字段：

- `LLM_BASE_URL`
- `LLM_API_PREFIX`
- `LLM_API_KEY`

`gemini` 字段：

- `GEMINI_BASE_URL`
- `GEMINI_API_PREFIX`
- `GEMINI_API_KEY`

## 7. Checkpoint 配置

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `CHECKPOINT_EVERY_TICK` | `1` | 是否启用运行档案 |
| `CHECKPOINT_INCLUDE_LOGS` | `1` | snapshot/delta 是否包含当前 tick 日志 |
| `CHECKPOINT_SNAPSHOT_INTERVAL_TICKS` | `60` | 完整 snapshot 间隔 |
| `CHECKPOINT_DIR` | `checkpoints/<WORLD_JSON>` | 输出目录 |
| `CHECKPOINT_RESTORE_FILE` | 空 | 指定恢复文件 |
| `CHECKPOINT_RESTORE_DIR` | 空 | 指定恢复目录，取最新 archive snapshot |

启用后会写入：

- `manifest.json`
- `snapshots/snapshot_*.json.gz`
- `deltas/deltas_*.jsonl.gz`
- `simulation_log.json`

创建新的 `ArchiveRecorder` 会清理目标目录中的旧 archive 输出。需要保留历史运行时，请使用不同的 `CHECKPOINT_DIR`。

## 8. TaskPolicy

`TaskPolicy` 不属于 runtime config，而是写在 recipe 中：

```json
{
  "process": {
    "duration": {"mode": "fixed", "value": 6},
    "assign_to": "self",
    "task_policy": {
      "interrupt_mode": "pause_keep_progress",
      "allow_voluntary_interrupt": true,
      "allow_voluntary_cancel": true
    }
  }
}
```

支持字段：

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `interrupt_mode` | `pause_keep_progress` | `forbidden`、`pause_keep_progress`、`pause_reset_progress`、`cancel`、`fail` |
| `allow_voluntary_interrupt` | `true` | 是否允许 agent 主动中断 |
| `allow_voluntary_cancel` | `true` | 是否允许 agent 主动取消 |

感知层只暴露必要摘要，例如自己的 `vitals`、当前任务是否可中断/取消，不默认暴露其他 agent 的内部体征。

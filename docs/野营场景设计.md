# 野营生存场景设计

## 状态

本文是 Camping world Package 的当前场景设计。它合并了原先的野营策划案和详细设计，并以当前
`packages/Camping/`、`runtime_config.camping.package.smoke.json` 和 KERN 运行时为准。

本文同时区分三类内容：

- **已实现**：当前 Package 和内核已经提供的行为。
- **目标**：场景希望具备、但尚未落地的行为。
- **待决**：需要先确定契约再改动内核的设计。

架构事实以代码为准；`docs/kernel_backlog.md` 记录跨场景的质量缺口和暂缓事项。

## 场景目标

“深林三十日”是四名 Agent 的低规则密度野外驻留实验。Agent 通过采集、储存、烹饪、休息、
探索、修缮、分享和对话应对资源与环境压力。展示重点是长期策略差异、分工、互助、回避和
记忆对后续选择的影响，不设单一胜负目标。

目标运行长度为 30 天：1 tick 为 1 分钟，总计 43200 tick。当前 smoke 配置只用于 Package
装配和基础运行回归，不代表 30 天行为验收。

## 世界

### 地点和路径

当前世界包含七个地点：

| ID | 用途 |
| --- | --- |
| `camp_main` | 主营地，包含公共箱、火堆和庇护所 |
| `stream` | 取水、钓鱼 |
| `forest` | 木材、浆果和野菜 |
| `hillside` | 预留石材、草药和天气线索 |
| `hunter_cabin` | 探索补给 |
| `wetland` | 蘑菇、草药和风险资源 |
| `lookout` | 预留天气和远处资源线索 |

路径是有向边，当前距离固定。`Travel` 只允许选择当前地点出发且未阻塞的路径。

### Agent

当前使用四个 `camper` 实例：

| ID | 名称 | 倾向 |
| --- | --- | --- |
| `camper_organizer` | 林澈 | 整理物资和长期计划 |
| `camper_explorer` | 许野 | 外出探索 |
| `camper_repairer` | 周砚 | 设施和装备维护 |
| `camper_caregiver` | 沈禾 | 分享、照看和对话 |

所有角色都可执行基础行为。人格通过 `AgentSetting` 和记忆影响 workflow/LLM 决策，不构成
硬职业锁。

### 资源和设施

当前可用资源主链为：木材、浆果、野菜、生鱼、熟鱼、罐头和公共储物箱。火堆支持点燃和烹饪
生鱼。清水、草药、石材、绳索、绷带和修补材料已经有模板，但其完整下游用途仍是目标。

当前设施：

- `CampStorageBox`：关闭时隐藏内容，打开后透明；可 `OpenContainer`、`TakeItem` 和
  `StoreItem`。
- `Campfire`：初始 `extinguished`；可消耗木材以 `LightCampfire`，`lit` 时可 `CookFood`。
- `Shelter`：当前是可观察设施；休息仅要求角色处于 `camp_main`。

## 行为

### 已实现

| 行为 | 类型 | 当前效果 |
| --- | --- | --- |
| `Travel` | 长任务 | 按路径距离完成地点移动 |
| `GatherWood` | 长任务 | 林地获得木材，消耗体力和压力 |
| `FetchWater` | 长任务 | 溪流获得清水 |
| `GatherPlants` | 长任务 | 林地或低地随机获得食物/草药 |
| `Fish` | 长任务 | 溪流随机获得生鱼或空结果 |
| `Explore` | 长任务 | 小屋随机获得罐头、绳索或空结果 |
| `LightCampfire` | 长任务 | 消耗背包木材并加入 `lit` |
| `CookFood` | 长任务 | 消耗生鱼，生成熟鱼 |
| `CampRest` | 长任务 | 主营地恢复体力并降低压力 |
| `Consume` | 即时 | 执行 `EdibleComponent.on_consume_bundle` 后销毁物品 |
| `OpenContainer` / `CloseContainer` | 即时 | 改变容器透明度 |
| `TakeItem` / `StoreItem` / `Give` | 即时 | 移动物品 |
| `Talk` | 即时 | 发起同地点有界群聊 |

### 目标

- 每小时营养和体力压力；低营养、低体力状态和中断。
- 晴天、小雨、暴雨及其对采集、移动、低地风险和火堆的影响。
- 火堆持续耗材、熄灭和夜间休息收益。
- 山坡、观察点和低地探索的明确产出与风险。
- 修补庇护所、制作绷带、使用草药/医疗物品、饮水和热汤。
- 资源分享、设施问题和环境变化的可观察事件。

## 对话和记忆

`Talk` 不携带目标，发起者提供一条开场白。`StartConversation` 在单个 tick 内：

```text
确定同地点参与者
-> 生成发起者开场白和其他参与者的 Speak/Pass transcript
-> 将每句成功发言作为 Say interaction 写入一个 child bundle
-> 向同地点可感知角色广播 interaction inbox
-> 默认 LLM workflow 在下一次决策时将 inbox 转为短期记忆
```

对话预算按地点、按 tick 限制；当前默认上限为 4 句。每个非发起参与者在一次会话中最多回应
一次。对话没有跨 tick 持续对象；后续交流需要下一 tick 重新发起。

任何 DialoguePolicy 或 interaction 写入失败都会回滚整段 transcript 的世界写入。LLM 请求本身
属于外部运行，无法随世界事务回滚。

场景不定义关系分值或对话剧本。分享、协作和冲突通过 `Say` interaction、物品流动和记忆记录
观察。后续若研究问题需要可比较的社会机制，再设计明确的关系或承诺组件。

## 当前移动模型

当前 `Travel` 是延迟到达任务：创建任务时绑定起点、终点和路径距离；任务进行期间实体仍登记在
起点 `Location.entities_in_location`；完成时才执行 `MoveEntity` 到终点。感知层对
`Travel/InProgress` 做特殊过滤，以免其他 Agent 看见仍登记在起点的旅行者。

这个模型能推进任务，但地点索引和感知语义并不一致。例如，旅行者被普通感知隐藏，却可能仍被
依赖地点索引的系统当作起点参与者。

### 待决：Task 管理的移动 placement

目标模型：`Travel` Task 直接管理移动期间的 placement。旅行者出发后从起点地点移除；在
Task 进行中，实体逻辑上不属于任何 `Location`；到达时由 Task completion bundle 原子进入
终点。

Task 应持有或可恢复移动所需事实：`origin_location_id`、`destination_location_id`、路径身份或
等价路径事实、出发 tick、进度、完成、暂停和中断策略。旅行者及其背包在移动任务进行中不参与
任何同地点查询、地点占用或地点对话。

这不是只改 `Travel` recipe 的数据任务。实现前需要专项设计并覆盖：top-level placement 的
checkpoint/archive schema、runtime snapshot、全量视图、感知、对话参与者、interaction 位置、
中断/取消后的停留语义、路径中途阻塞，以及 Task 出发、到达、取消的 placement
effect/binder/handler 契约。

在该设计落地前，维持当前延迟到达模型，并在所有地点参与者筛选中排除 `Travel/InProgress`。

## 运行和验证

当前 Package 配置：

```text
runtime_config.camping.package.smoke.json
packages/Camping/kern-package.json
```

基础检查：

```powershell
& .\.venv\Scripts\python.exe tools\scenario_lint.py --config runtime_config.camping.package.smoke.json
& .\.venv\Scripts\python.exe default_orchestrator.py --config runtime_config.camping.package.smoke.json
```

lint 只验证结构和引用。行为验收应使用确定性场景测试覆盖容器、移动、采集、点火、烹饪、进食、
对话、任务中断和 checkpoint restore。

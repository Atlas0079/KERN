# 2026 年与 KERN 最接近的项目与文章

> 调研日期：2026-07-28
> 范围：优先考察 2026 年首次公开、发布正式版本、持续实质开发，或在 2026 年发表的项目与论文。项目能力只采用官方仓库、官方文档、正式 release 和论文原文作为依据。

## 一、结论摘要

截至 2026-07-28，和 KERN **整体定位最接近**的公开项目是 **SiliSocS**。它与 KERN 都把 LLM 多智能体仿真视为可复现实验系统，而不是普通的 Agent 工作流：环境、Agent、调度和评估由配置组合，运行产生配置快照、事件、模型调用记录和指标；其 2026 年 EASE 论文更直接把“消除单体式、临时拼装的社会仿真”作为目标。SiliSocS 仓库建立于 2024 年，但首批正式 release 和对应论文均在 2026 年，因此应标记为“**2026 年首次正式发布**”，不能写成“2026 年首次出现源代码”。

第二梯队是 **Concordia、POSIM 和 AgentSociety 2**：

- **Concordia** 在通用世界、自然语言动作、Game Master 合法性/结果解析以及可组合 Component 上最像 KERN；它始于 2023 年，但 2026 年仍有正式版本和实质代码更新。
- **POSIM** 是 2026 年新项目和新论文，Hawkes 时间引擎、结构化可检查状态、环境共演化、checkpoint 反事实轨迹都很接近 KERN 的研究用途；其领域限定于社交媒体舆情，也没有公开声明 KERN 式 Bundle 原子提交与世界回滚。
- **AgentSociety 2** 在模块化环境、大规模执行、trace/replay 和研究工作流上接近，且 2026 年更新最活跃；它的重心是分布式 LLM Agent 平台，KERN 的重心是权威世界状态和确定性结算内核。

若只问“2026 年最值得 KERN 直接吸收的文章”，优先级是：

1. **EASE Configuration / SiliSocS**：实验结构与复现清单；
2. **Toward Temporal Realism**：把“何时行动”和“行动什么”分离；
3. **MiroBench**：用真实讨论分布检验仿真，而不是只检验文本是否像人；
4. **Silicon Society Cookbook**：把模型、网络等设计选择当成实验变量；
5. **LLM-Based Social Simulations Require a Boundary**：限制推断边界并报告行为方差。

没有一个候选在公开材料中同时覆盖 KERN 的全部强契约：**统一 Effect 绑定、EffectBundle 世界事务、失败回滚、提交后 Event 才触发 Reaction、外部副作用分类、运行期冻结 Catalog、Package artifact identity 精确恢复**。这组能力仍是 KERN 最鲜明的差异化。

## 二、KERN 的实际定位

KERN 的根 README 将其定义为基于 ECS 和数据驱动离散事件仿真（DES）的 LLM 多智能体实验内核，目标是可配置、可复用、可审计。[KERN README](../readme.md)

结合当前实现与架构文档，KERN 可以概括为六个边界：

1. **世界状态与决策分离**：workflow、decision、recipe、reaction 读取世界并产生 `ActionIntent` 或 `EffectBundle`；`WorldExecutor` 才能写 `WorldState`。[当前架构](current_architecture.md#2-状态与行为边界)
2. **声明式动作解析**：Agent 自然语言/结构化意图先匹配 Recipe 和 Condition，再编译为 Effect；合法但当前不可执行的动作返回 `ActionRejected`，契约失败则终止运行。
3. **事务化结算**：一个 `EffectBundle` 是一个世界事务；任一 Effect 失败会恢复世界快照，成功 Event 仅在最外层 Bundle 提交后进入 Reaction FIFO。[Executor 实现](../KERN/executor/executor.py)
4. **确定性时间与反应链**：每 tick 先进行被动结算，再按稳定顺序授予主动 turn；Reaction 按配置顺序和 FIFO 处理。
5. **运行期可扩展但身份固定**：一个 world Package 与若干 capability Package 组合各自的 Component、Effect、Recipe 和 Reaction；Catalog 在执行前冻结。
6. **可审计与精确恢复**：snapshot、run archive、failure evidence 和可选 LLM trace 分离；checkpoint 使用 `package_identity.v2` 校验实际加载的 manifest、数据和扩展代码。

因此，本报告不把 AutoGen、CrewAI、LangGraph 这类“通用 Agent 编排/任务完成框架”当作直接同类。它们可以成为 KERN 的 Agent 决策层或工具层，却不以可复现实验世界、世界变更结算和社会仿真有效性为核心产品对象。

## 三、比较标准

“接近程度”按下列六项综合判断。排序是架构和研究用途的定性判断，不是对项目质量的总评分。

| 维度 | 对 KERN 的含义 | 判断问题 |
| --- | --- | --- |
| 研究目的 | LLM/多智能体仿真与可复现实验 | 项目主要用于模拟社会/环境演化，还是完成一次任务？ |
| 世界模型 | 独立、权威、可检查的环境状态 | 环境是否独立于 Agent 推理，Agent 是否只能经受控接口影响它？ |
| 动作与结算 | Intent -> 校验/规则 -> 状态变更 | 是否区分 Agent 提议、动作解析、世界结果和后续事件？ |
| 时间与反应 | tick、调度、事件传播和环境共演化 | 是否有明确时间模型、激活策略、事件或反应链？ |
| 复现与审计 | 配置、轨迹、checkpoint、trace、身份校验 | 能否重放、比较并解释一次运行，恢复时能否识别代码/数据漂移？ |
| 可扩展范围 | 数据驱动场景、组件/规则扩展 | 是通用仿真内核，还是固定领域应用？ |

时间状态采用三个互斥描述层次：

- **2026 年首次发布**：2026 年出现首个公开 release，或项目仓库和论文均在 2026 年公开。
- **截至 2026 年仍实质活跃**：项目早于 2026 年，2026 年有功能代码或正式 release；单纯徽章、二维码、依赖机器人更新不算强证据。
- **2026 年文章**：论文首版或会议版本在 2026 年；若首版早于 2026 年但在 2026 年修订/录用，单独说明。

## 四、最接近的项目（按整体接近度排序）

### 1. SiliSocS / EASE

**时间标签：2026 年首次正式发布；2026 年文章；截至 2026 年实质活跃。**

官方仓库元数据表明仓库建立于 2024-07-03；首个正式 release `v0.1.0` 发布于 2026-06-02，随后 `v0.2.0` 和 `v0.3.0` 分别于 6 月 12 日和 6 月 26 日发布。EASE 论文首版于 2026-05-28 提交。[仓库元数据](https://api.github.com/repos/sandbox-social/silisocs)；[v0.1.0](https://github.com/sandbox-social/silisocs/releases/tag/v0.1.0)；[v0.3.0](https://github.com/sandbox-social/silisocs/releases/tag/v0.3.0)；[arXiv:2605.30258](https://arxiv.org/abs/2605.30258)

**为什么最接近**

- EASE 将系统拆成 Environment、Agents、Simulation engine、Evaluation，YAML 配置每一轴；KERN 则将 Package/world data、workflow、recipe/reaction、Effect/Executor 和 archive 分开。两者都把实验组合与可复现性提升为一等架构问题。
- SiliSocS 的 engine 明确控制 Agent “何时、如何行动”，环境由 Game Master 和 backend 组合；KERN 的 `TurnScheduler`、`TurnRunner`、Recipe 编译和 Executor承担相近职责。
- SiliSocS 输出 resolved config、`action_events.jsonl`、模型请求响应、指标和 SQLite 环境数据，并提供 study schema 展开 hypothesis、condition、scenario、seed；这与 KERN 的 snapshot/archive/failure/trace 共同服务于研究审计。
- 2026 年 `v0.3.0` 还加入 validate-then-apply 的原子 checkpoint restore、运行 provenance 和完成标记，进一步接近 KERN 的恢复与身份校验方向。[官方 README](https://github.com/sandbox-social/silisocs/blob/main/README.md)；[v0.3.0 release](https://github.com/sandbox-social/silisocs/releases/tag/v0.3.0)

**关键差异**

- SiliSocS 的公开边界是 Agent/GM/backend/engine/Evaluation；KERN 另有 EffectSpec、Binder、Handler、Bundle transaction 和提交后 Reaction 这些更细的世界写入协议。
- SiliSocS `v0.3.0` 所称原子性针对 checkpoint 的“先验证、后应用”。公开材料没有声称一次动作包含的多项世界写入具备 KERN 式全 Bundle 回滚。
- SiliSocS 已内置 Twitter/Reddit/Mastodon、资源市场和虚拟空间，并具备完整 study runner；KERN 当前公开可运行 world Package 只有 Camping，但 KERN 的 Package identity 和外部副作用边界更严格。

**可直接借鉴**：将 hypothesis、condition、seed、evaluator 和结果摘要提升为 KERN 上层“研究编排”契约；不要把它并入内核事务层。

### 2. Concordia

**时间标签：早于 2026 年发布；截至 2026 年仍实质活跃。**

Concordia 仓库建立于 2023 年，技术报告也是 2023 年。2026 年连续发布 `v2.2.0`、`v2.3.x` 和 `v2.4.0`；7 月仍有新场景、MCP 工具支持和 Component 行为修正等实质提交。[官方仓库](https://github.com/google-deepmind/concordia)；[v2.4.0](https://github.com/google-deepmind/concordia/releases/tag/v2.4.0)；[2026-07-22 功能提交](https://github.com/google-deepmind/concordia/commit/93090bba797277b212209449addb105117e62147)

**为什么接近**

- 官方将 Concordia 定义为 grounded physical、social 或 digital environments 中的 generative agent-based model 库，而非任务 Agent 编排器。
- Player entity 提出自然语言动作，Game Master 检查物理合理性并转译为结果。这和 KERN 的 Agent 意图不能直接写世界、必须先经过 Recipe/Condition/Effect 的原则高度相似。
- Entity、Component 和 Engine 构成模块化 game engine；prefab 可以组合 Agent 和 Game Master。概念上接近 KERN 的 Entity/Component、Package 和 runtime 装配。

**关键差异**

- Concordia 的核心抽象偏向由 LLM/Component 组成的 Entity 与 Game Master 叙事解析；KERN 的权威状态转换是具名、可绑定、可记录、可回滚的 Effect。
- Concordia 官方 README 强调广泛应用和可组合 Agent 行为，没有公开承诺 EffectBundle 原子事务、Reaction 提交可见性或 Package artifact identity。
- SiliSocS 明确承认受 Concordia 启发并提供兼容桥；因此对 KERN 而言，Concordia 更像最接近的“通用交互模型”，SiliSocS 更像最接近的“研究运行系统”。

来源：[官方 README](https://github.com/google-deepmind/concordia/blob/main/README.md)；[技术报告 arXiv:2312.03664](https://arxiv.org/abs/2312.03664)；[Design Pattern arXiv:2507.08892](https://arxiv.org/abs/2507.08892)

### 3. POSIM

**时间标签：2026 年新项目；2026 年文章；截至 2026 年实质活跃。**

官方仓库元数据显示 POSIM 建立于 2026-01-28；论文首版于 2026-03-25 发布；仓库 6 月仍更新核心公开材料与样例数据。[仓库元数据](https://api.github.com/repos/DeepCogLab/posim)；[arXiv:2603.23884](https://arxiv.org/abs/2603.23884)；[官方仓库](https://github.com/DeepCogLab/posim)

**为什么接近**

- Social-BDI Agent 把 identity、psychology、event opinion、emotion 维护成显式、可检查状态，并保留 belief -> desire -> intention -> action 决策链；这与 KERN 把 Agent memory、DecisionFrame、ActionIntent 和世界状态分开的目标一致。
- Hawkes 自激点过程与昼夜调制决定分钟级 Agent 激活，环境包含社交网络、推荐和热榜；它和 KERN 的 wake policy、tick、被动 Reaction 一样，把“何时行动”留给显式仿真机制。
- 官方架构将 Agent、环境、评估通过接口解耦；反事实模块从 checkpoint 分叉轨迹并评估 intervention，和 KERN 的可恢复、可审计实验目标十分接近。
- 论文同时做个体机制、集体现象和统计一致性三层验证，研究方法成熟度高于只展示叙事案例的框架。

**关键差异**

- POSIM 是面向社交媒体舆情的领域框架，角色、网络、推荐、舆情阶段和干预均围绕该领域；KERN 的目标是可由 Package 组合的通用世界内核。
- POSIM 的公开 README 称 pip 包和完整系统仍在开发中，数据与部分组件将逐步发布；当前成熟度不能仅凭论文结果等同于完整可复用平台。
- checkpoint 在 POSIM 中用于反事实轨迹；公开资料没有说明它是否校验代码/数据身份，也未说明动作写入具有事务回滚。

来源：[官方 README](https://github.com/DeepCogLab/posim/blob/main/README.md)；[论文原文](https://arxiv.org/abs/2603.23884)

### 4. AgentSociety 2

**时间标签：项目始于 2025 年；2026 年推出并持续发布 2.x；截至 2026 年高度活跃。**

官方仓库建立于 2025-02-06。AgentSociety 论文首版为 2025 年；推荐使用的 AgentSociety 2 在 2026 年持续发布，调研日前最新为 `2.8.4`（2026-07-27）。[仓库元数据](https://api.github.com/repos/tsinghua-fib-lab/AgentSociety)；[2.8.4 release](https://github.com/tsinghua-fib-lab/AgentSociety/releases/tag/agentsociety2-v2.8.4)；[arXiv:2502.08691](https://arxiv.org/abs/2502.08691)

**为什么接近**

- 官方将 v2 定义为面向社会科学研究和实验设计的 LLM-native agent simulation platform。
- 环境 Component 与工具可插拔，Agent 是 workspace-bound stateless record，由 Ray task 驱动；运行服务、trace 和 replay 由统一代理提供。
- catalog-driven JSONL replay、DuckDB 读取和 distributed tracing 与 KERN archive/trace 的目标相似；大规模分布式执行则是 KERN 当前没有强调的优势。
- v1 城市仿真具有 mobility、economy、social 模块；v2 将重点转向多推理模式、MCP 和研究技能。

**关键差异**

- AgentSociety 2 的公开定位更接近“LLM-native 分布式 Agent 仿真与研究平台”；KERN 更强调一次世界状态转换如何被验证、提交、回滚和触发 Reaction。
- replay/trace 证明运行可观察，不自动等于 deterministic world replay 或事务恢复；官方摘要没有给出 KERN 对应的 Bundle 原子性与 package identity 契约。
- AgentSociety 的扩展面包含文献搜索、假设、实验设计和论文写作，明显超出 KERN 内核范围。

来源：[官方 README](https://github.com/tsinghua-fib-lab/AgentSociety/blob/main/README.md)；[v2 文档](https://agentsociety2.readthedocs.io/)

### 5. SocaSim

**时间标签：2026 年文章；截至调研日未核实到官方开源仓库。**

SocaSim 论文首版于 2026-07-07 提交。它构建包含社会网络演化、信任动态和规范传播的环境，让 Agent 重复参与集体行动实验，并支持逐轮微观路径追踪与反事实干预。[arXiv:2607.06080](https://arxiv.org/abs/2607.06080)

**为什么接近**

- 它把社会理论直接落实为环境状态、互动机制和可观察的宏观模式，符合 KERN “world data + rules + state mutation + archives”的研究思路。
- round-by-round 路径和 counterfactual intervention 与 KERN 的事件/档案/恢复能力具有天然接口关系。

**关键差异**

- SocaSim 是围绕 Putnam 社会资本理论构建的研究框架，不是通用仿真内核。
- 截至 2026-07-28，arXiv 摘要未给出代码链接，本次也未在论文标题/项目名的官方 GitHub 检索中核实到作者仓库。因而只能评价论文公开的方法，不能推断其软件事务、扩展或持久化能力。

### 6. OASIS

**时间标签：2024 年论文/仓库，主要版本在 2025 年；2026 年仓库仍有活动，但实质开发证据偏弱。**

OASIS 是 Twitter/Reddit 式社交媒体仿真器，官方称可扩展到一百万 Agent，提供 23 类动作、动态社交网络和推荐系统。[官方仓库](https://github.com/camel-ai/oasis)；[论文 arXiv:2411.11581](https://arxiv.org/abs/2411.11581)

**为什么仍列入**

- 其平台环境、受限动作空间、Agent graph、手工动作与 LLM 动作共存，以及 `reset/step` API，和 KERN 的 Agent 意图进入受控世界接口有明显相似性。
- 它在大规模社交传播、极化和从众研究上是 KERN 社交平台类 Package 的直接参考对象。

**关键差异与时间 caveat**

- OASIS 固定在社交媒体平台领域；KERN 的世界、Component、Effect 和规则可以由 Package 改变。
- 官方 release 列表截至调研日最后版本是 `v0.2.5`（2025-12-04）。2026 年提交多数是二维码自动更新；可确认的 4 月改动主要是 token 成本说明，不能据此称其 2026 年仍在高强度功能开发。[v0.2.5](https://github.com/camel-ai/oasis/releases/tag/v0.2.5)；[2026-04-12 提交](https://github.com/camel-ai/oasis/commit/336c9c6ed7583b863ef0536a870f7d510d55502c)
- OASIS 的主要优势是规模和社交平台机制，不是 KERN 的通用事务与恢复契约，所以排名低于前五项。

## 五、2026 年最相关的文章和评测

这些文章不一定提供一个比上述项目更接近 KERN 的软件内核，但直接指出 KERN 应怎样设计调度、实验和验证。

### A. EASE Configuration Facilitates A Reproducible Science of LLM Social Simulations

- **日期**：2026-05-28 首版。
- **贡献**：用 Environment、Agents、Simulation engine、Evaluation 的配置分解取代临时、单体式模拟器，并用 study schema 组织研究问题、条件和评估。
- **与 KERN 的关系**：是最接近 KERN Package composition 和可审计运行目标的 2026 方法论文；其 study/evaluation 层可作为 KERN 上层实验协议参考。
- **来源**：[arXiv:2605.30258](https://arxiv.org/abs/2605.30258)；[SiliSocS 官方仓库](https://github.com/sandbox-social/silisocs)

### B. Toward Temporal Realism in City-Scale Crisis Response Simulation using LLM Agents

- **日期**：2026-06-18 首版。
- **贡献**：真实群体行动具有 bursty、heavy-tailed 时间结构；同步 LLM-only simulator 几乎无法复现。论文用数据校准的 self-excitation gate 和 crisis regime 决定 Agent 何时激活，LLM 只决定参加何种任务与是否承诺。
- **与 KERN 的关系**：直接支持 KERN 现有 `AgentWakePolicyComponent`/TurnScheduler 的方向。未来调度器应允许由显式数据模型产生 wake，而不是让每个 Agent 每 tick 固定调用 LLM。
- **来源**：[arXiv:2606.19904](https://arxiv.org/abs/2606.19904)

### C. MiroBench: Benchmarking Realism in Agentic Simulation of Real-world Discussions

- **日期**：arXiv 记录首版为 2026-05-10；官方代码仓库建立于 2026-05-10。
- **贡献**：用 4,292 个真实 Reddit thread，从重复/语义同质化、叙事内容、毒性/攻击性、结构复杂度四方面做统计检验；五个领域和五个模型仍与真实分布明显不匹配。
- **与 KERN 的关系**：KERN 的 deterministic、auditable runtime 只保证实验可重现，不保证 Agent 行为具有外部效度。社交传播 Package 应把这类分布检验接到 archive 的 evaluator 上。
- **来源**：[arXiv:2606.14715](https://arxiv.org/abs/2606.14715)；[官方代码](https://github.com/yyu6/MiroBench)

### D. The Silicon Society Cookbook: Design Space of LLM-based Social Simulations

- **日期**：2026-04-30 首版。
- **贡献**：系统考察 base model、Agent 连接方式等设计变量及其交互；结论显示设计空间并非简单可加，base LLM 是影响结果最大的变量。
- **与 KERN 的关系**：Package identity 能固定输入与扩展文件，但实验复现还需要把模型版本、采样参数、网络生成方式和 seed 当作显式 treatment/provenance，而不是只留在自由文本配置中。
- **来源**：[arXiv:2605.00197](https://arxiv.org/abs/2605.00197)

### E. LLM-Based Social Simulations Require a Boundary

- **日期**：首版 2025-06-24，2026-07-12 更新为 v3，标注 ICML 2026 Position Paper；因此它是“2026 会议/修订文章”，不是“2026 首发文章”。
- **贡献**：LLM 容易生成“平均人”，均值对齐不能替代行为异质性；验证深度应匹配研究问题，报告均值同时报告方差，并将主张限制在仿真能支持的层级。
- **与 KERN 的关系**：KERN 能保证机制和轨迹可查，却不能仅凭工程可审计性推出社会科学有效性。报告与 evaluator 应明确微观、分布、结构、因果四类主张的边界。
- **来源**：[arXiv:2506.19806](https://arxiv.org/abs/2506.19806)

### F. From Plausible to Causal: Counterfactual Semantics for Policy Evaluation in Simulated Online Communities

- **日期**：2026-04-05 首版，2026-04-15 更新 v2。
- **贡献**：把“看起来可信”与因果推断分开，区分必要因果和充分因果，并强调结果只能解释为 simulator-conditional causal estimate。
- **与 KERN 的关系**：KERN 的 checkpoint、Package identity 和 deterministic settlement 有利于构造可比较反事实，但仍需明示识别假设、共同随机数/seed 策略、干预位置与 fidelity 限制。

## 七、对 KERN 的具体启示

1. **优先补“研究编排层”，保持内核边界不动。** SiliSocS 已证明 hypothesis × condition × scenario × seed × evaluator 的显式 study schema 很有价值。KERN 可以在 Package/runtime 之上增加这一层，让每次运行继续使用现有 Executor 和 archive。
2. **把 wake/时间模型做成正式扩展点。** POSIM 和 Temporal Realism 都表明同步轮询会扭曲群体动力学。KERN 已有 wake policy，可进一步支持数据校准的 point process、自激事件和 crisis regime，同时继续由 scheduler 决定何时调用 LLM。
3. **将“工程复现”和“社会科学有效性”分别验收。** Package identity、事务和 trace 解决前者；MiroBench、Cookbook 和 Boundary 论文要求另行验证分布、异质性、结构和因果边界。
4. **保留 KERN 的事务化差异。** 邻近项目强调 GM、平台、规模或实验配置，但公开资料很少给出“多个状态写入作为一个世界事务，失败时回滚，Event 提交后才触发反应”的强语义。这是 KERN 应继续测试和清晰文档化的核心优势。
5. **不要把规模宣称直接当成可复现性。** AgentSociety 和 OASIS 的分布式/百万 Agent 能力值得参考，但规模、行为真实性、确定性和审计是四个不同指标，应独立测量。

## 七-A、定位修正：LLM 玩家与文字沙盒

如果 KERN 的实际目标是“让 LLM 玩一个由文字描述、规则驱动、状态持久的沙盒游戏”，那么它与社会人口仿真平台的关系是应用邻近，与以下三类工作的关系更直接：

1. **Concordia 式 generative game engine**：LLM Player 提出自然语言动作，Game Master 依据 grounded world 判断动作和结果。它在整体交互模型上最接近 KERN；KERN 的区别是用 Recipe、Binder、Effect 和事务执行器替代较自由的叙事裁决。
2. **TextArena/TextWorld/Zork 式文字游戏环境**：环境返回文本观察，LLM 输出文本动作，游戏引擎维护权威状态并给出反馈。它们最适合作为 KERN Agent 能力 benchmark，而不是 KERN 内核架构的直接替代品。
3. **角色一致性与长程游戏研究**：这类工作关注 LLM 是否持续扮演同一个角色、保持目标和策略、记住失败并避免重复动作。它们补足的是 KERN 的 Workflow/Memory/Policy 层，不应进入世界事务层。

### “行为一致性”的四种不同含义

| 一致性 | 要检验的问题 | KERN 当前主要责任 |
| --- | --- | --- |
| 世界一致性 | 动作是否符合位置、物品、资源和规则，失败是否污染状态 | 强：Recipe/Condition、Binder、EffectBundle 回滚 |
| 角色一致性 | 行为是否持续符合 persona、价值倾向和关系 | 部分：可保存 persona/memory；主要取决于 Workflow/模型 |
| 策略一致性 | 相似状态下是否保持目标，能否解释改计划的原因 | 部分：DecisionFrame、trace、action feedback 提供证据 |
| 时间一致性 | 是否记住已经发生的事实、承诺、失败和任务进度 | 世界事实强；Agent 如何压缩、检索和使用记忆仍需评测 |

因此，KERN 不应承诺“强制 LLM 行为一致”。更准确的主张是：**KERN 固定世界事实和合法行动边界，保存可审计轨迹，使 LLM 的角色漂移、策略反复和记忆失败能够被测量。**

### 2026 年直接相关工作

- **Codified Finite-state Machines for Role-playing**（CFSM）：从文字角色档案生成可解释状态机，以显式潜在状态和转移约束角色一致性。它与 KERN 的数据化状态/规则思路很接近，但作用对象是角色状态，不是世界事务。[arXiv:2602.05905](https://arxiv.org/abs/2602.05905)
- **AdaMARP**：以 `[Thought]`、`(Action)`、`<Environment>` 和 Speech 分离思考、动作、环境与发言，并用显式 Scene Manager 管理换场、选说话者和动态加入角色；轨迹级评估包含 character consistency、environment grounding 和 narrative coherence。[arXiv:2601.11007](https://arxiv.org/abs/2601.11007)
- **ARPM**：把长期人格一致性视为外部、可追踪的记忆治理问题，区分静态知识和动态经历，并测试 context clearing、噪声与跨模型 handoff 下的 persona drift。它最适合参考 KERN 的 Agent memory 层。[arXiv:2605.14802](https://arxiv.org/abs/2605.14802)
- **MEMO**：面向多回合、多 Agent 文字游戏，通过持久经验库、自博弈和 prompt/context 搜索降低 run-to-run variance；它关注的是游戏策略稳定与性能，不等同于角色一致性。[arXiv:2603.09022](https://arxiv.org/abs/2603.09022)；[官方代码](https://github.com/openverse-ai/MEMO)
- **Playing With AI: Zork**：直接测试 LLM 玩经典文字冒险。论文报告模型平均完成度低于 10%，常重复无效动作、策略坚持不一致，并且无法从历史失败中学习。这说明“提供完整对话历史”并不足以产生稳定沙盒玩家。[arXiv:2602.15867](https://arxiv.org/abs/2602.15867)
- **One Policy, Infinite NPCs**：面向 life-simulation NPC 的 persona-conditioned shared RL policy，用轨迹一致性目标保持 persona 可辨识性和实时性能。它证明真正稳定、规模化的 NPC 行为可能需要受训策略，而不只是每回合调用通用 LLM。[arXiv:2605.23652](https://arxiv.org/abs/2605.23652)
- **AI YOU Town**：用持续更新的人格档案、Bayesian update 和分层记忆锚点降低百回合、多 Agent、对抗条件下的 trait drift；更接近“长期数字角色”，不是规则沙盒引擎。[arXiv:2607.10539](https://arxiv.org/abs/2607.10539)

### 对 KERN 的建议

1. 将产品/论文定位改为“**LLM-controlled text sandbox**”或“**grounded generative game simulation kernel**”，社会仿真作为一种 Package/研究用途。
2. 保持 `ActionIntent -> Recipe -> EffectBundle -> committed world state` 为核心。这条链保证行动后果一致，却不替 LLM 决定它应当想什么。
3. 给 Workflow 增加可替换的 policy-state/memory 实验位，分别比较纯上下文、结构化目标状态、检索记忆、CFSM/BDI 和训练策略；不要把某一种人格算法固定进内核。
4. 建立文字沙盒玩家评测：重复无效动作率、承诺违背率、目标切换次数及理由、已知事实矛盾率、任务完成率、相同 checkpoint 多次采样的行动分布，以及不同模型/seed 的轨迹方差。
5. 用 checkpoint fork 做一致性测试：从同一世界状态和同一 Agent memory 多次继续运行，区分允许的随机多样性、无理由策略漂移和世界事实错误。

- 候选优先覆盖：通用 generative agent-based simulation、可复现社会仿真、城市/社交媒体多 Agent 仿真、明确时间引擎、反事实和真实性评测。

### 局限

- 2026 年尚未结束；7 月 28 日之后出现的论文、release 和代码不在结论内。
- arXiv 是预印本，一些 2026 论文仍在审稿；本文只陈述其公开方法与实验主张，不把它们视为已完成同行评审。
- 本次没有对所有外部项目执行安装、源码级事务审计或同一场景 benchmark。“未核实”严格表示官方材料不足，不能解释为确定不存在。
- GitHub `updated_at` 会被 issue、star 等活动改变，所以“实质活跃”优先依据正式 release 和功能 commit；OASIS 已因此降级表述。
- SocaSim 截至检索日未找到可核实的官方代码链接；不采用名称相近但作者关系不明的仓库。
- KERN 仍处于本地项目阶段，当前可运行 world Package 数量和外部复现实证少于成熟公开项目；本报告对 KERN 的判断来自当前源码，不代表已完成跨机器复现实验。

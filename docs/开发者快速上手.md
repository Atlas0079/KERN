# 开发者快速上手

本文面向第一次接触本项目的开发者或 IDE agent，目标是在本地完成一次可运行的 KERN 模拟，并理解当前 runtime 边界。

## 1. 环境准备

推荐使用仓库虚拟环境：

```powershell
.\venv\Scripts\python.exe --version
.\venv\Scripts\python.exe -m pip install -r requirements.txt
```

如果本机虚拟环境不可用，Codex 桌面环境通常提供 bundled Python；具体路径以当前会话为准。

## 2. Runtime 配置

runtime 配置文件使用统一 JSON 结构：

```json
{
  "env": {
    "USE_LLM": "0",
    "WORLD_JSON": "CompanionRobot/World.json"
  }
}
```

配置解析顺序：

1. CLI 参数 `--config`
2. 环境变量 `RUNTIME_CONFIG_FILE`
3. 默认文件 `runtime_config.json`

当前仓库只应提交无密钥示例配置，例如：

- `runtime_config.example.json`
- `runtime_config.camping.smoke.json`

真实本地配置可能包含 API token，必须保持 ignored。不要提交 `runtime_config.json`、`runtime_config.local.json`、`runtime_config.*.local.json`、`runtime_config.companion_robot*.json` 或其他带密钥的 config。给 IDE agent 的稳定规则是：**把本地 config 加入 ignore，只提交脱敏示例。**

## 3. 运行方式

无 LLM smoke：

```powershell
.\venv\Scripts\python.exe default_orchestrator.py --config runtime_config.camping.smoke.json
```

使用本地幼儿园/豆豆配置时，配置文件通常在本机而非仓库：

```powershell
.\venv\Scripts\python.exe default_orchestrator.py --config runtime_config.companion_robot.json
```

`CompanionRobot` 现在只是历史目录名和本地配置名前缀；当前场景语义已经转为“幼儿园里的豆豆”。

## 4. KERN Runtime 边界

KERN 提供核心能力：

- 加载 scenario 数据：world、entities、recipes、reactions、bundles
- 构建 `WorldState`
- 推进 game time 和 tick
- 用 condition 匹配 recipe/reaction
- 编译 command 为 effect bundle
- 通过 executor 修改世界
- 记录事件、交互、checkpoint/archive
- 每 tick 给 agent 一个调度脉冲，由 agent 自己的规则决定是否思考

上层 app 负责产品编排：

- 选择场景和 runtime config
- 决定何时推进 tick、推进多少 tick
- 决定何时暂停给现实对话
- 选择 action provider / LLM provider
- 将用户输入整理为记忆、建议或外部事件
- 决定 UI 如何展示 outbox、状态和日志

因此，KERN 可以每 tick 询问 agent，但“是否思考、为什么思考、如何选择”应由 agent 自己的策略、规则和 workflow contract 决定。

## 5. Workflow Contract

当前 agent workflow 接口：

```python
mem_patch = workflow.build_memory_patch_data(ws_view, recipe_db, actor_id)
decision = workflow.decide(ws_view, recipe_db, actor_id, reason, mode_context)
```

`decision` 支持：

- `{"type": "apply_commands", "commands": [...]}`
- `{"type": "noop"}`
- `{"type": "error", "error": {"kind": "temporary|business|contract", "code": "...", "message": "..."}}`

workflow 不直接返回内部 operation。runtime 会把 `apply_commands` 通过 `InteractionEngine` 编译为 effect bundle，再交给 executor 执行。

## 6. 常用检查

```powershell
.\venv\Scripts\python.exe -m unittest tests.test_time_conditions tests.test_gametime
.\venv\Scripts\python.exe -m unittest tests.test_world_state_entity_perception
.\venv\Scripts\python.exe tools\scenario_lint.py --config runtime_config.camping.smoke.json
```

如果要验证本地幼儿园配置，使用你自己的 ignored config：

```powershell
.\venv\Scripts\python.exe tools\scenario_lint.py --config runtime_config.companion_robot.smoke.json
```

## 7. 输出文件

启用 checkpoint 时，运行输出写入 `checkpoints/`，包括：

- `manifest.json`
- `snapshots/snapshot_*.json.gz`
- `deltas/deltas_*.jsonl.gz`
- `simulation_log.json`

这些是 runtime 产物，不应作为源代码改动提交。

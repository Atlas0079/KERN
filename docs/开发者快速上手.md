# 开发者快速上手

本文面向第一次接触本项目的开发者或 IDE agent，目标是在本地完成一次可运行的 KERN 模拟，并理解当前 runtime 边界。

## 1. 环境准备

请使用自己的 Python 3.10+ 解释器。建议先创建并激活虚拟环境；下文统一使用 `python`，如果系统中的命令名称不同，请替换为实际解释器命令或绝对路径。

```powershell
python --version
python -m pip install -r requirements.txt
```

## 2. Runtime 配置

runtime 配置文件使用统一 JSON 结构：

```json
{
  "packages": [
    {"path": "Packages/Camping", "world": true}
  ],
  "env": {
    "USE_LLM": "0"
  }
}
```

配置解析顺序：

1. CLI 参数 `--config`
2. 未传 `--config` 时使用项目根目录下的 `runtime_config.json`

当前仓库只应提交无密钥示例配置，例如：

- `runtime_config.camping.package.smoke.json`
- `runtime_config.su7_crisis.package.smoke.json`

真实本地配置可能包含 API token，必须保持 ignored。不要提交 `runtime_config.json`、`runtime_config.local.json`、`runtime_config.*.local.json`、`runtime_config.*.local*.json` 或其他带密钥的 config。给 IDE agent 的稳定规则是：**把本地 config 加入 ignore，只提交脱敏示例。**

`MAX_TICKS` 表示世界 `total_ticks` 的绝对上限，不是“本次再推进多少 tick”。如果从 checkpoint 恢复后需要继续推进固定步数，应优先使用 `KernRuntime.advance_ticks(count)`。

## 3. 运行方式

无 LLM smoke：

```powershell
python default_orchestrator.py --config runtime_config.camping.package.smoke.json
```

SU7Crisis 社交世界包 smoke：

```powershell
python default_orchestrator.py --config runtime_config.su7_crisis.package.smoke.json
```

如果要使用真实 LLM key，请放在 ignored 的本地配置里，例如 `runtime_config.camping.llm.local.json`。不要把密钥写入 committed config。

## 4. KERN Runtime 边界

KERN 提供核心能力：

- 加载 scenario 数据：world、entities、recipes、reactions、bundles
- 构建 `WorldState`
- 推进 game time 和 tick
- 用 condition 匹配 recipe/reaction
- 编译 command 为 effect bundle
- 通过 executor 修改世界
- 记录事件、交互、checkpoint/archive
- 每 tick 给 agent 一个调度脉冲，由 agent 自己的规则决定是否思考

上层 app 负责产品编排：

- 选择场景和 runtime config
- 决定何时推进 tick、推进多少 tick
- 决定何时暂停给现实对话
- 选择 action provider / LLM provider
- 将用户输入整理为记忆、建议或外部事件
- 决定 UI 如何展示 outbox、状态和日志

因此，KERN 可以每 tick 询问 agent，但“是否思考、为什么思考、如何选择”应由 agent 自己的策略、规则和 workflow contract 决定。

当前 SDK 入口是 `KernRuntime`：

```python
from KERN import KernRuntime

runtime = KernRuntime.from_config(".", "runtime_config.camping.package.smoke.json")
runtime.advance_ticks(10)
```

## 5. Workflow Contract

当前 agent workflow 接口：

```python
mem_patch = workflow.build_memory_patch_data(ws_view, recipe_db, actor_id)
decision = workflow.decide(ws_view, recipe_db, actor_id, reason, mode_context)
```

`decision` 支持：

- `{"type": "apply_commands", "commands": [...]}`
- `{"type": "noop"}`
- `{"type": "error", "error": {"kind": "temporary|business|contract", "code": "...", "message": "..."}}`

workflow 不直接返回内部 operation。runtime 会把 `apply_commands` 通过 `InteractionEngine` 编译为 effect bundle，再交给 executor 执行。

`build_memory_patch_data(...)` 是当前 runtime 的必需钩子。默认 `WORKFLOW_CONTRACT_ON_ERROR=fail_fast`；如果 workflow 缺少必需 hook 或返回不符合契约，runtime 会按错误处理路径中止。只有显式配置为 `degrade_to_noop` 时才会降级为空操作。

## 7. 输出文件

启用 checkpoint 时，运行输出写入 `checkpoints/`，包括：

- `manifest.json`
- `snapshots/snapshot_*.json.gz`
- `deltas/deltas_*.jsonl.gz`
- `simulation_log.json`

这些是 runtime 产物，不应作为源代码改动提交。

默认输出目录是仓库下的 `checkpoints/`。如果在配置中显式设置相对 `CHECKPOINT_DIR`，该路径会按当前工作目录解析。

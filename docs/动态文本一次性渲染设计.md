# 动态文本一次性渲染设计

## 当前状态

第一版已实现运行时动态文本渲染，入口为 `KERN.dynamic_text`。

已接入字段：

1. `CreateEntity.spawn_patch.name`
2. `AddMemoryNote.text`
3. `StartConversation.opening_text`
4. `EmitEvent.payload` 中明确的文本键

第一版不会为了旧写法保留兼容路径。如果数据结构不符合当前契约，应直接迁移数据，让数据适配系统，而不是让运行时继续兼容旧数据。

## 设计目标

动态文本用于在少量明确文本字段中引用执行上下文，并在写入世界状态、事件或记忆前渲染成普通字符串。

目标：

1. 只在白名单字段中生效。
2. 只渲染一次。
3. 渲染结果立即静态化。
4. 复用现有 `self` / `target` / `event_entity` / `event` / `param` 引用体系。
5. 不支持脚本、条件、循环、函数调用或表达式运算。

## 核心原则

### 动态文本是渲染，不是绑定

模板只在执行时求值一次。例如：

```json
{
  "effect": "CreateEntity",
  "template": "Corpse",
  "spawn_patch": {
    "name": "{target.entity_name}的尸体"
  }
}
```

如果执行时 `target.entity_name` 是 `张三`，写入实体后的名字就是：

```text
张三的尸体
```

后续世界状态中不应继续保留 `{target.entity_name}`。

### 只允许白名单字段

第一版白名单如下：

- `CreateEntity.spawn_patch.name`
- `AddMemoryNote.text`
- `StartConversation.opening_text`
- `EmitEvent.payload.message`
- `EmitEvent.payload.text`
- `EmitEvent.payload.description`
- `EmitEvent.payload.detail`
- `EmitEvent.payload.reason`
- `EmitEvent.payload.summary`
- `EmitEvent.payload.name`
- `EmitEvent.payload.label`

`EmitEvent.payload` 支持递归遍历，但只渲染上述文本键。其他 payload 键即使包含 `{...}` 也不会被渲染。

### 标识字段禁止动态文本

以下字段不能使用动态文本：

- `effect`
- `template`
- `component`
- `property`
- `status_id`
- `ref`
- `entity_id`
- `task_id`
- `source_ref`
- `target`
- 枚举值和类型名

这些字段必须保持纯标识符。需要动态行为时，应通过 context、`param:` 或明确的文本字段表达。

### 失败必须显式暴露

白名单文本字段中的占位符如果无法解析，渲染失败。effect 应返回 `ExecutorError`，不能静默保留原模板，也不能猜测默认值。

例如：

```json
{
  "message": "hello {unknown.value}"
}
```

会失败，而不是输出：

```text
hello {unknown.value}
```

这样可以尽早暴露错误数据，避免模板泄漏进运行时状态。

## 支持语法

占位符格式：

```text
{path}
```

支持的路径来源：

- `{self}`：当前执行上下文中的 `self_id`
- `{target}`：当前执行上下文中的 `target_id`
- `{event_entity}`：当前事件实体 id
- `{self.entity_name}`
- `{target.entity_name}`
- `{event_entity.entity_name}`
- `{self.location_id}`
- `{target.location.location_name}`
- `{event.location_id}`
- `{param:text}`
- `{param:item.id}`
- `{param.text}`

路径读取复用 `KERN.query.core.resolve_value()` 和 `KERN.entity_ref_resolver`。

## 一次性渲染语义

动态文本只处理原始模板中的占位符，不递归处理渲染结果。

例如 context 参数：

```json
{
  "parameters": {
    "note": "met {target.entity_name}"
  }
}
```

模板：

```text
{self.entity_name}: {param:note}
```

第一版输出：

```text
Eris: met {target.entity_name}
```

不会继续把参数值里的 `{target.entity_name}` 再渲染一次。需要最终文本包含目标名字时，数据应直接写成：

```text
{self.entity_name}: met {target.entity_name}
```

## 接入点

### CreateEntity.spawn_patch.name

`CreateEntity` 只对 `spawn_patch.name` 做动态文本渲染。

`spawn_patch.components` 不属于第一版动态文本白名单。不要依赖运行时为 component patch 做模板兼容；如果需要动态描述字段，应先把该字段纳入明确白名单，再更新数据。

### AddMemoryNote.text

`AddMemoryNote.text` 在写入 `MemoryComponent` 前渲染。

如果 recipe 使用：

```json
{
  "text": "param:text"
}
```

则 binder 会先解析 `param:text`，executor 再对解析后的文本做一次动态文本渲染。

### StartConversation.opening_text

`StartConversation.opening_text` 在第一句对话写入 transcript 和事件前渲染。

### EmitEvent.payload

`EmitEvent.payload` 只渲染明确文本键。示例：

```json
{
  "effect": "EmitEvent",
  "event_type": "MessageBroadcasted",
  "payload": {
    "source_ref": "target",
    "message": "来自{target.entity_name}的广播"
  }
}
```

`message` 会渲染，`source_ref` 不会渲染。

## 不做的事

第一版明确不支持：

- 全局字符串自动渲染
- 递归二次渲染
- 在标识字段中插值
- 表达式运算
- 条件判断
- 循环
- 函数调用
- 为旧数据格式保留兼容路径
